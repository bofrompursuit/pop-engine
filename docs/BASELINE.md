**Artifact checksums:** the current ruleset row above carries a `sha256` digest, per `ARCHITECTURE-FUTURE.md` §14 step 5, which requires a published artifact to carry version, checksum, changelog and approval metadata before this manifest is updated. The digest is **SHA-256 over the exact bytes of the file at the path in that row**, with nothing normalised, no key reordering and no whitespace stripped, so it is reproducible with one command and depends on nothing but the file:

```
sha256sum rules/nyc-rules.v2.7.json
```

It lives here rather than inside the artifact because a digest stored in the file it covers would change the bytes it describes. `pnpm check:baseline` recomputes it and fails on a mismatch, so a ruleset edited without republishing, or a row left pointing at a digest that no longer matches, breaks the build rather than going unnoticed. Stating the algorithm and the coverage is the point: a checksum whose derivation is not written down cannot be verified by anyone later.

**Version conventions (current):** ruleset `nyc.vMAJOR.MINOR` · rules schema `popengine-rules/v2` · fixtures follow the ruleset version they derive from. Full semver-per-artifact (per `docs/proposals/baseline-manifest-codex-draft.md`) is a Phase 2 upgrade.
